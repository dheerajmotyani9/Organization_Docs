Business Rules (BR)

7 rules
IDRuleDescriptionApplies to
BR‑FH‑01Initial Survey decision routingAt the Initial Survey stage only: FE Accept routes to GM for final approval; FE Reject routes DIRECTLY to the Contractor with the GM not involved at all. This differs from every later cycle.Screens 1, 2, 3
BR‑FH‑02Re‑Inspection always routes to GMFrom the first Re‑Inspection RFI onward, the FE's re‑inspection result — whether satisfied or not — is always submitted to GM for decision. There is no direct FE→Contractor path inside the loop.Screen 6, FE Re‑Inspection node
BR‑FH‑03Uncapped continuous Re‑Inspection LoopIf GM rejects the FE's re‑inspection report, the RFI returns to the Contractor and the cycle (Contractor → GM → SQC → FE → GM) repeats. No maximum number of cycles is stated — it continues until GM accepts.Screens 3‑7, GM Decision node
BR‑FH‑04FE reassignment — SQC discretionDuring any Re‑Inspection cycle, SQC may assign the RFI to the same FE or a different FE. Reassignment is optional and operational. If reassigned, only the newly assigned FE may view/act on the RFI; the previous FE loses update access.Screen 5, FE Reassignment scenario
BR‑FH‑05Full history visible to new FEWhen a new FE is assigned, the complete survey history, previous remarks and attachments remain visible to them for reference and audit, even though they cannot edit the previous FE's entries.Screen 5, Screen 6 timeline
BR‑FH‑06loop_iteration counterA counter increments by 1 every time the Contractor raises a new Re‑Inspection RFI on the same case. Starts at 1 for the Initial Survey. Exposed on the RFI Dashboard for monitoring.Screen 8, all Re‑Inspection screens
BR‑FH‑07Same case ID retainedA Re‑Inspection RFI reuses the original case/RFI ID — no new record is created for any cycle of the loop.Screen 3, Re‑Inspection Loop flow
